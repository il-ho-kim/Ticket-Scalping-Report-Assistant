# PRD v0.3 — "암표 신고 준비 도우미"

> v0.2 → v0.3: 실제 구현(`index.html`, `js/`, `api/kopis.js`)에 맞춰 흐름·화면을 6단계로 고치고, 판단 보조 질문, 붙여넣기·자동 인식 방식, KOPIS 공식 정보 대조, 현재 지원 범위를 반영했다.

## 1. 문제

온라인 암표신고센터로 신고할 때

- 공연인지 스포츠인지에 따라 신고 사이트가 달라, 어디로 신고해야 하는지부터 헷갈린다.
- 발견한 거래가 신고 대상인지 판단하기 어렵다. [재판매 목적으로 시스템을 우회 또는 방해하여 입장권을 구매하는 부정구매와 입장권 판매자의 동의를 받지 않고 상습 또는 영업으로 웃돈을 얹어 입장권을 판매·알선하는 부정판매] 중 어디에 해당하는지 구분하기도 어렵다.
- 증빙 정리가 번거롭다. 중고거래·SNS 게시글이 삭제되기 전에 캡처해야 하고, 게시 URL, 게시 일시, 판매가와 정가, 판매자 계정 정보를 따로 정리해야 한다.
- 공연·경기명, 일시, 장소, 좌석, 정가 대비 판매가, 거래 플랫폼 등을 빠짐없이 서술하는 것이 귀찮다.

## 2. 고객

- 티켓팅에 실패한 뒤 중고거래·SNS에서 웃돈 거래 게시글을 발견한 공연·스포츠 팬
- 암표 게시글을 발견해 삭제되기 전에 즉시 신고하려는 시민
- 신고 대상 여부 판단과 신고 내용 작성에 부담을 느끼는 신고자
- 신고포상금에 관심이 있어 요건을 갖춘 신고를 하고 싶은 신고자

## 3. 불편의 크기

티켓팅마다 겪는 암표상들의 만행.

- 암표방지법 시행 후(2026.8.28\~9.16) 신고가 하루 평균 245.4건
- 최근 1년(2025.9\~2026.8) 누적 공연 암표 신고는 7,639건에 달한다.

## 4. 핵심 가치

암표 거래를 발견했을 때 필요한 판단·증빙·서술의 부담을 줄여, 필요한 정보가 갖춰진 암표 신고를 올바른 창구에 빠르게 접수할 수 있게 한다.

- **판단 부담 감소**: 분야(공연·스포츠)별 신고 창구를 안내하고, 세 가지 질문으로 부정구매·부정판매 해당 가능성을 참고용으로 알려준다.
- **증빙 부담 감소**: 게시글 캡처나 붙여넣은 글에서 공연명·일시·장소·좌석·가격·플랫폼·예매처·판매자·게시일시를 자동으로 채우고, 공연예술통합전산망(KOPIS) 공식 정보와 대조해 정가·장소 등을 바로잡게 한다. 캡처 속 얼굴·전화번호 등은 직접 칠해 가릴 수 있다.
- **서술 부담 감소**: 입력한 정보와 참고 판정으로 신고 내용 초안을 만들고, 북마크릿으로 공식 신고 양식에 옮겨 채운다.

## 5. 핵심 흐름

1. 사용자가 서비스가 하는 일과 하지 않는 일을 확인한다
2. 사용자가 분야를 고르고 신고 창구를 확인한다
3. 사용자가 질문에 답해 부정구매·부정판매 참고 판정을 받는다
4. 사용자가 캡처를 올리거나 게시글을 붙여넣고, 자동으로 채워진 정보를 확인·수정한다
5. 사용자가 항목별 요약과 신고 초안을 확인하고 복사한다
6. 사용자가 공식 사이트로 이동해 본인인증 후 북마크릿으로 내용을 채우고 직접 제출한다

## 6. 화면 여섯 개

단일 페이지 마법사 형태다. 상단에 진행 표시(`n / 6 · 단계명`)와 뒤로 가기, 하단에 [다음] 버튼이 있다.

- **1 · 시작**
  - 보이는 것: 서비스 소개, "이 서비스가 하지 않는 것" 목록
  - [신고 준비 시작하기] → 2
- **2 · 분야**
  - 보이는 것: 공연/스포츠 선택지, 선택한 분야의 신고 창구 미리보기
  - 공연: 한국콘텐츠진흥원 온라인 암표 신고센터
  - 스포츠: "준비 중" 안내만 보이고 다음으로 넘어갈 수 없다
- **3 · 판단**
  - 보이는 것: 질문 세 개(각 예/아니오/모름), 참고 판정 카드와 면책 문구
    - Q1. 매크로 등 예매 시스템 우회 프로그램으로 구매한 티켓인가?
    - Q2. 여러 건을 반복적으로 웃돈 받고 판매하는 것으로 보이는가?
    - Q3. 판매자 동의 없이 제3자가 알선·중개하는 거래인가?
  - 판정 규칙: Q1 예 → 부정구매 가능성 / Q2 또는 Q3 예 → 부정판매 가능성 / 그 외 → 정보가 더 필요함
  - 판정 결과에 맞는 문장이 초안에 들어간다. 답하지 않아도 넘어갈 수 있다.
- **4 · 증빙**
  - 보이는 것
    - 캡처 업로드 박스(최대 5장, 썸네일을 눌러 검게 칠해 가리기)
    - 게시글 내용 붙여넣기 칸
    - 지금 쓸 수 있는 자동 인식 방식 안내, [자동으로 읽기] 버튼, 인식이 안 될 때 볼 진단 정보
    - 정보 확인 입력칸: 각 칸에 자동/직접입력/공식 정보 출처 표시
    - KOPIS 공식 정보 카드: 후보 공연 선택, 항목별 차이 비교, [바꾸기]/[다른 항목 모두 바꾸기]
  - 필수 항목(*): 공연명, 공연 일시, 정가, 판매 가격, 공연 장소, 거래 플랫폼, 예매처, 게시글 URL
  - 선택 항목: 게시일시, 좌석번호, 판매자 계정·닉네임
  - 거래 플랫폼: 중고나라, 번개장터, 당근마켓, 티켓베이, SNS, 기타
  - 예매처: NOL티켓, YES24, 티켓링크, 멜론티켓, 쿠팡플레이, 기타
  - 필수 항목을 모두 채워야 [다음]이 켜진다
- **5 · 초안**
  - 보이는 것: 항목별 요약 카드(출처 표시, 항목별 복사 버튼), 신고 문구 초안 텍스트박스, 전체 복사 버튼, 면책 문구
- **6 · 이동**
  - 보이는 것: 공식 사이트 열기 버튼(ent.kocca.kr/ticket/receive.do), 본인인증 안내, 북마크릿 사용 순서와 [신고 내용 채우기] 북마크릿, 드래그가 안 될 때 쓰는 코드 복사 버튼, 항목 대응표
  - [사이트 열기]/[북마크릿 클릭] → 서비스 밖(공식 사이트)
  - [처음으로 돌아가기] → 입력값을 모두 지우고 1로

## 7. 자동 인식과 공식 정보 대조

### 자동 인식 방식

환경에 따라 가장 정확한 방식을 자동으로 고른다.

| 우선순위 | 방식 | 조건 | 비고 |
|---|---|---|---|
| 1 | 캡처 이미지 읽기 | claude.ai 아티팩트 안에서 열었고 이미지 읽기가 허용됨 | Claude가 캡처를 직접 읽는다 |
| 2 | 캡처 글자 읽기 | 캡처를 올렸고 브라우저 OCR(Tesseract.js)을 쓸 수 있음 | 기기 안에서 처리하고 캡처를 밖으로 보내지 않는다. 처음 한 번 엔진·글자 데이터(약 8.4MB)를 CDN에서 받는다 |
| 3 | 붙여넣은 글 읽기 | 아티팩트 안이지만 이미지 읽기는 안 됨 | 붙여넣은 글을 Claude가 읽는다 |
| 4 | 붙여넣은 글에서 직접 찾기 | 그 외 | 페이지에 내장된 규칙(`js/parse.js`)으로 찾는다 |

- 캡처 인식이 막히면 붙여넣은 글로 다시 시도한다.
- 자동으로 채운 값도 사용자가 확인·수정할 수 있다.

### KOPIS 공식 정보 대조

- 공연명을 채우면 KOPIS에서 공식 공연 정보를 찾는다. 대조 항목은 공연명, 기간, 공연장, 좌석별 가격, 공연 시간, 예매처다.
- 입력값과 다른 항목은 차이만 보여준다. 사용자가 [바꾸기]를 눌러야 값이 바뀐다.
- 브라우저는 서버 함수(`api/kopis.js`, Vercel)를 거쳐 KOPIS를 부른다. 이용 키는 서버 환경변수에만 둔다.
- 키나 서버 함수가 없는 환경에서는 "지금은 공식 정보 확인을 쓸 수 없어요"만 보이고, 다른 기능은 그대로 동작한다.

## 8. 북마크릿 자동 채우기

- 공식 신고 양식에서 채우는 항목: 공연명, 공연일시, 정가, 부정거래 가격, 부정거래 건수(1), 게시일시, 좌석번호, 신고내용(초안), 거래경로(사이트), 예매처, 부정거래 상세정보(링크주소), 부정거래 판매자정보
- 채우지 않는 항목: 성명·휴대폰·이메일·본인인증·개인정보 동의. 제출 버튼도 누르지 않는다.
- 공식 사이트의 화면 구조가 바뀌면 일부 항목이 채워지지 않을 수 있다. 그럴 때는 항목 대응표를 보고 직접 옮긴다. 캡처 이미지는 "증빙자료 첨부"에 직접 올려야 한다.

## 9. 현재 범위와 제약

- **스포츠 분야 미지원**: 선택지만 있고 "준비 중"으로 막혀 있다. 공연 분야만 끝까지 진행할 수 있다.
- **배포 형태**: 정적 파일(`index.html`)만으로 동작한다. KOPIS 대조만 서버 함수가 필요하다.
- **저장 없음**: 입력값과 캡처는 페이지 안에만 있다. 새로고침하거나 창을 닫으면 사라진다.

## 10. 안 할 것

- **로그인·회원가입**: 계정 생성, 프로필 관리, 소셜 기능
- **대리 제출**: 공식 신고 시스템에 자동으로 접수하는 기능. 본인인증과 최종 제출은 신고자가 공식 사이트에서 직접 한다. 북마크릿도 개인정보 항목과 제출 버튼은 건드리지 않는다.
- **신고 후 처리**: 접수 결과, 처리 현황 조회, 과징금·포상금 진행 알림
- **판매자 추적**: 판매자 신원 조회, 계정 모니터링, 여러 게시글 수집 등 신고 범위를 넘어서는 정보 수집
- **위반 여부 확정**: 법적 판단이나 포상금 지급 가능성 보장. 판단 보조와 안내까지만 한다.
- **장기 보관**: 개인 신고 이력, 원본 캡처 아카이브
