## 실행

정적 파일만으로 동작해요. GitHub Pages에 그대로 올리거나, 로컬에서는 아무 정적 서버로 열면 돼요.

```sh
python3 -m http.server 8000   # http://localhost:8000
```

`index.html`을 파일로 바로 열면(`file://`) 브라우저 보안 정책 때문에 캡처 글자 인식이 동작하지 않을 수 있어요.

## 캡처 자동 인식

- 캡처를 올리고 [캡처에서 자동으로 읽기]를 누르면, 브라우저 안에서 [Tesseract.js](https://github.com/naptha/tesseract.js)로 글자를 읽고(`js/ocr.js`) 내장 규칙으로 공연명·일시·장소·좌석·가격·플랫폼·예매처·판매자·게시일시를 찾아 채워요(`js/parse.js`).
- 캡처는 기기 밖으로 전송되지 않아요. 처음 한 번은 인식 엔진(약 4MB)과 한국어·영어 글자 데이터(약 4.4MB)를 jsdelivr CDN에서 받고, 이후에는 브라우저에 저장된 것을 써요.
- claude.ai 아티팩트 안에서 열면 Claude가 캡처를 직접 읽는 경로를 먼저 써요.

## 공식 공연 정보 확인 (공연예술통합전산망 KOPIS)

4단계 카드의 검색칸에 연도 + 아티스트(예: "2026 실리카겔")를 넣고 [찾기]를 누르면, 그해 공연 중 공연명에 그 이름이 들어간 공연을 지난 공연까지 모두 보여줘요. 고른 공연의 공식 정보(공연명·기간·공연장·좌석별 가격·공연 시간·예매처)와 입력값을 비교해요.
- 서버 함수 `api/kopis.js`: `?q=2026 실리카겔`(낱말마다 그해 1년을 한 번에 조회해 합침, 목록만), `?id=PF…`(공연 하나의 상세). 다른 항목은 차이를 보여주고, 사용자가 [바꾸기]를 눌러야 바뀌어요.

- 브라우저는 `api/kopis.js`(Vercel 서버 함수)를 부르고, 이 함수가 KOPIS 오픈 API를 대신 불러요. 이용 키는 웹페이지에 들어가지 않아요.
- 설정: Vercel → 프로젝트 → Settings → Environment Variables에 `KOPIS_API_KEY`(KOPIS에서 받은 서비스키)를 넣고 다시 배포해요.
- 점검: `https://<배포 주소>/api/kopis?ping=1`을 열면 키 설정 여부와 KOPIS 연결 상태를 보여줘요(키 값은 보여주지 않아요).
- 키가 없거나 서버 함수가 없는 곳(로컬에서 파일로 열 때 등)에서는 "지금은 공식 정보 확인을 쓸 수 없어요"만 나오고, 다른 기능은 그대로 동작해요.

## 버튼 한 번으로 채우기

4단계에서 [캡처에서 자동으로 읽기]를 한 번 누르면 아래가 이어서 자동으로 진행돼요. 사용자가 직접 고친 칸은 덮어쓰지 않아요.

1. **캡처 읽기**: 캡처의 글자를 읽어 칸을 채워요(출처 표시: "캡처에서 읽음").
2. **판매글 찾기**(티켓베이, URL이 비어 있을 때): 캡처와 같은 판매글이 하나면 주소를 넣어요("캡처와 대조함").
   - 그 판매글에 적힌 값으로 공연 일시·판매가·정가(좌석 등급 정가)·좌석·게시일시·공연장·공식 공연명을 채워요("판매글에서 확인").
   - 글자 인식이 틀린 값(예: 좌석)도 이때 바로잡혀요.
3. **공식 정보(KOPIS)**: 공연명과 함께 티켓베이의 아티스트 영문명(예: "엑소 (EXO)"의 EXO)과 공연장으로 찾아요.
   - KOPIS는 정식 공연명(예: "EXO PLANET #6, EXhOrizon [dot]")으로 등록돼 있어서, 중고거래 표기("엑소 2026 - 서울")만으로는 못 찾는 경우가 많기 때문이에요.
   - 공연이 하나로 정해지면 다른 칸을 공식 정보로 고쳐요("공식 정보로 고침"). 공식 예매처가 하나면 예매처도 골라요.
4. **남은 항목 안내**: 아직 비어 있는 필수 항목을 알려줘요.

## 게시글 주소 찾기·대조 (티켓베이)

게시글 URL은 신고 필수 항목이지만, 앱에서 캡처만 하면 주소를 모르는 경우가 많아요. 4단계에서 거래 플랫폼이 티켓베이면 "게시글 주소 찾기" 카드가 나와요.

- **찾기**: 캡처에서 읽은 공연명·공연 일시·판매가·좌석으로 티켓베이에서 같은 판매글을 찾아요. 캡처에 상품번호가 보이면 그 번호로 바로 찾아요. 캡처와 같은 글로 판정된 글만 보여주고, [이 주소 쓰기]로 URL 칸에 넣어요.
- **대조**: URL 칸에 티켓베이 판매글 주소를 넣거나 붙여넣으면 캡처와 같은 글인지 바로 확인해요.
- **판정은 두 가지예요**: 같은 글 / 다른 글.
  - 같은 글: 판매가와 공연일이 같고, 좌석은 양쪽에 다 있는 부분(층·등급·구역·열·번호)이 모두 같을 때예요. 상품번호가 보이면 번호만으로 정해요.
  - 다른 글: 위 항목 중 하나라도 다르면 다른 글이고, 어느 항목이 다른지 보여줘요.
  - 공연명·게시 시각은 참고로만 보여줘요.
- **동작 방식**: `api/listing.js`(Vercel 서버 함수)가 티켓베이 공개 페이지(로그인 불필요)를 대신 조회해요.
  - 조회하는 곳: 공연 검색, 그 회차·좌석 등급의 판매글 목록, 판매글 상세예요. 한 번 찾는 데 요청은 5번 이하예요.
  - 신고할 글 한 건을 찾는 데만 쓰고 저장하지 않아요.
  - 판매자 내부 번호나 설명글은 화면에 보내지 않아요.
- **한계**: 판매가 끝났거나 삭제된 글은 찾을 수 없어요. 같은 회차·가격·좌석의 글이 여러 개면 등록 시각을 보고 사용자가 골라야 해요.

## 테스트

```sh
npm install
npm test              # 내장 파서·KOPIS 연동·게시글 주소 대조 단위 테스트
npm run test:e2e      # 합성 캡처로 브라우저에서 인식 → 입력칸 비교, 공식 정보 확인·게시글 주소 찾기 흐름 (Playwright, Chromium)
npm run fixtures      # tests/fixtures/templates/*.html 로 합성 캡처 다시 만들기
```

합성 캡처(`tests/fixtures/captures/`)는 실제 서비스 화면을 흉내 낸 가짜 화면이고, 공연·판매자 정보도 모두 가상이에요.
